# Hazard-Free 32-bit Pipelined RISC-V Processor

## Overview

This project implements a 32-bit pipelined processor based on the RISC-V instruction set architecture (ISA). The processor uses a multi-stage pipeline to improve instruction throughput while incorporating hardware mechanisms to detect and resolve data and control hazards.

The design was implemented using SystemVerilog and developed for FPGA-based simulation and verification.

## Features

- 32-bit RISC-V processor
- Five-stage instruction pipeline
- Hazard detection
- Data forwarding
- Pipeline registers
- Control hazard handling
- Branch support
- Arithmetic and logical operations
- Load and store operations
- RISC-V instruction execution
- Dedicated multiplication support
- Modular SystemVerilog RTL design
- FPGA-compatible architecture

## Pipeline Architecture

The processor uses a five-stage pipeline:

1. Instruction Fetch (IF)
2. Instruction Decode (ID)
3. Execute (EX)
4. Memory Access (MEM)
5. Write Back (WB)

The general pipeline flow is:

IF
 ↓
ID
 ↓
EX
 ↓
MEM
 ↓
WB

Multiple instructions can therefore be processed simultaneously, with each instruction occupying a different pipeline stage.

## Pipeline Stages

### 1. Instruction Fetch (IF)

The Program Counter is used to fetch the instruction from instruction memory.

The PC is normally incremented to fetch the next instruction.

### 2. Instruction Decode (ID)

The instruction is decoded and its operands are read from the register file.

The control unit generates the control signals required by later pipeline stages.

Hazard detection logic also checks whether the current instruction depends on data that is still being produced by an earlier instruction.

### 3. Execute (EX)

The ALU performs arithmetic and logical operations.

The execute stage also handles:

- Address calculation
- Branch comparisons
- Immediate operations
- Forwarded operands
- Multiplication operations

### 4. Memory Access (MEM)

Load and store instructions access the data memory during this stage.

Other instructions simply pass their results through the pipeline.

### 5. Write Back (WB)

The final result is written back into the register file.

The result may originate from:

- ALU
- Data memory
- Multiplier
- Other execution units

## Pipeline Registers

Pipeline registers separate the five major stages.

The design contains registers such as:

- IF/ID
- ID/EX
- EX/MEM
- MEM/WB

These registers store instruction data, operands, control signals, and intermediate results between pipeline stages.

## Hazard Handling

A major objective of this processor is to provide hazard-free execution.

A pipeline hazard occurs when instructions cannot safely execute in parallel because they depend on each other or because the program flow changes.

The processor handles important hazards using hardware logic.

## Data Hazards

A data hazard occurs when one instruction requires a value that is being generated by an earlier instruction.

Example:

ADD x5, x1, x2
SUB x6, x5, x3

The `SUB` instruction needs the value of `x5` produced by the previous `ADD`.

Instead of waiting unnecessarily for the value to reach the register file, the processor uses forwarding to directly provide the required result to the execute stage.

## Data Forwarding

Forwarding allows results from later pipeline stages to be directly sent back to the execute stage.

The forwarding unit checks the destination registers of instructions in:

- EX/MEM
- MEM/WB

and compares them with the source registers of the instruction currently executing.

If a dependency is detected, the appropriate forwarding path is selected.

Conceptually:

EX/MEM Result ─────┐
                   ↓
                Forward MUX → ALU
                   ↑
MEM/WB Result ─────┘

This significantly reduces pipeline stalls caused by data dependencies.

## Hazard Detection Unit

Some dependencies cannot be solved using forwarding alone.

For example, a load-use dependency may require the pipeline to wait for the loaded data.

The hazard detection unit monitors pipeline instructions and detects these situations.

When required, the processor can:

- Stall the pipeline
- Insert a bubble
- Prevent incorrect execution

This ensures correct instruction execution.

## Control Hazards

Control hazards occur when a branch or jump changes the Program Counter.

The processor includes control logic to handle changes in program flow and prevent incorrect instructions from being executed after a taken branch.

Branch control signals are propagated through the pipeline and the appropriate instructions are prevented from affecting the processor state when necessary.

## Multiplication Unit

The processor includes a hardware multiplication unit integrated into the execute stage.

It supports RISC-V multiplication operations such as:

- MUL
- MULH
- MULHSU
- MULHU

The multiplier receives operands from the execute stage and produces the required multiplication result.

The result is then passed through the remaining pipeline stages and eventually written back to the register file.

## ALU Operations

The ALU supports common RISC-V operations including:

- ADD
- SUB
- AND
- OR
- XOR
- SLT
- SLTU
- Logical shifts
- Arithmetic shifts

## Control Signals

The pipeline carries control information between stages.

Important control signals include:

- RegWrite
- ALUSrc
- MemRead
- MemWrite
- MemToReg
- Branch
- ALUOp

These signals are generated during instruction decoding and passed through the pipeline registers to control the appropriate hardware components.

The overall architecture can be represented as:

Instruction Memory
       ↓
      IF
       ↓
    IF/ID
       ↓
      ID
       ↓
    ID/EX
       ↓
      EX
   ┌───┴────┐
   ↓        ↓
  ALU    Multiplier
   └───┬────┘
       ↓
    EX/MEM
       ↓
      MEM
       ↓
    MEM/WB
       ↓
      WB

Register File

The forwarding and hazard detection units operate alongside the main datapath to maintain correct instruction execution.

## Hazard-Free Execution

The processor combines:

- Forwarding
- Hazard detection
- Pipeline stalls
- Control hazard handling

to ensure that instructions execute correctly even when dependencies exist between consecutive instructions.

This allows the processor to achieve higher instruction throughput compared with a single-cycle architecture.
